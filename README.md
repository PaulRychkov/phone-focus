# phone-focus

Приложение для Android из экосистемы productivity-ecosystem. Раз в 10 минут смотрит, какими приложениями ты пользуешься, и отправляет данные боту motivation-bot, чтобы бот помогал меньше залипать в телефоне.

Данные берутся из встроенного в Android механизма `UsageStatsManager` — того же, на котором работает системное приложение «Цифровой комфорт». Приложение OnePlus не требуется, сервисы Google тоже.

Телефон-цель: OnePlus 13T PKX110 (ColorOS 16 / Android 16), но ставится на любой Android начиная с 7.0.

## Из чего состоит

Почти всё написано на Go. На Kotlin — только то, что физически нельзя сделать иначе: Android требует, чтобы фоновая служба и приёмник загрузки были Java-классами, а обращения к системным экранам шли из Activity.

```
mobile/            Go: внешний API библиотеки (Configure, Push, Summary, Pending)
internal/usage/    Go: разбор событий, сессии, категории, расчёт снимка
internal/publish/  Go: формат CloudEvents, отправка по HTTPS, очередь на диске
internal/state/    Go: номер снимка и подпись прошлого замера
frontend/          React 18 + TypeScript + Vite + Tailwind: интерфейс приложения
android/app/       Kotlin: служба с таймером, приёмник загрузки, окно с WebView
```

Go собирается в библиотеку `focus.aar` через `gomobile bind`. Интерфейс собирается Vite в `android/app/src/main/assets` и показывается в WebView — так же, как Wails показывает React в pomodoro и tasks. Kotlin остаётся только там, где Android требует Java-класс: служба, приёмник загрузки и окно приложения.

Объём: Go — около 900 строк плюс тесты, интерфейс — около 280, Kotlin — около 290.

Интерфейс отдаётся WebView не по `file://`, а через перехват запросов к условному адресу `https://focus.app/` — WebView запрещает модулям JS грузиться с `file://` (проверено на эмуляторе, ошибка CORS в консоли), а перехват с правильными MIME-типами решает это без внешних библиотек.

## Что делает

- считает время каждого приложения за последние 10 минут и за сегодня, число запусков, число разблокировок;
- определяет, какое приложение открыто сейчас и с какого момента;
- относит приложения к категориям и отдельно считает время в отвлекающих;
- отправляет полный снимок как событие CloudEvents по HTTPS;
- при недоступной сети копит события на телефоне и досылает позже, повторы не задваиваются;
- держится в фоне службой переднего плана, поднимается после перезагрузки телефона.

## Формат события

CloudEvents 1.0, как во всей экосистеме: `source: phone`, `type: phone.usage.snapshot`. Внутри `data`: идентификатор устройства, `chat_id`, границы окна, текущее приложение с категорией и временем начала, состояние экрана, список приложений за окно и за сегодня (время, запуски, последнее использование), суммарное время в отвлекающих, число разблокировок, признак изменения и номер снимка.

## Настройка после установки

На экране приложения: выдать доступ к истории использования, отключить экономию батареи, указать адрес сервера, токен и `chat_id`, нажать «Сохранить и включить сбор». Пока адрес пустой, замеры копятся на телефоне и уйдут, когда адрес появится — приложение ни к какой конкретной сети не привязано.

На ColorOS дополнительно нужно разрешить автозапуск и закрепить приложение в списке недавних, иначе система выгрузит службу.
